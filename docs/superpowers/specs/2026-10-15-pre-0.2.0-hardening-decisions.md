## Recommendations that need a decision

### 1. Per-account login lockout (#322 E1-ui-auth-2)

Today both a per-address and a per-username bucket are charged on every attempt, so an
attacker who keeps guessing at `alice` holds `alice` in 429 for the real user.

Recommendation: charge the **username** bucket only on failed attempts (a success
refunds it), and key the per-address bucket on every attempt as now. A guesser still
slows to one try per 12 s per name, and a user who types the right password is not
locked out by someone else's failures. Accepted trade-off: the attacker can still keep
the bucket empty, so the real user's first attempts get 429 until it refills (about a
minute); a lockout that cannot be forced at all needs source+username keys, which lets
a botnet spread guesses. Wueschli's call: *refund on success* (recommended) or leave
as is for 0.2.0.

Side effect of hashing every name into 1024 buckets (the design suggested in #337):
a flood of random names can hold many buckets in `429`, including a legitimate
user's. It is bounded by the per-address bucket, so one source cannot do it at scale.

### 2. HTTP header-read and idle timeouts (#322 E5-6)

`wayhouse_http::tls::serve` and the plain path both go through `axum::serve`, which has no
header-read timeout, so a slow client can hold a connection open (slowloris). The TLS
handshake is already bounded (`client_hello_timeout`, `handshake_timeout`). A real fix
replaces `axum::serve` with a `hyper-util` connection builder with `header_read_timeout`
and a graceful-shutdown hook, and touches the TLS listener, connect info and shutdown.

Recommendation: **out of 0.2.0**. These servers are the control plane, not the data
plane; the fleet is expected to sit behind the operator's network boundary or a
reverse proxy that has its own timeouts (nginx, Traefik). Document that in
`docs/07-security-ddos.md` and file the replacement as a 0.3 item. Wueschli's call.

### 3. Where discovery may take `api` and `token_file` from (#322 F5-proxy-admin-1)

The Kubernetes source sends the pod service-account token to whatever `api` it is given,
and the Consul source sends the contents of `consul_token_file` to `consul_addr`. Both
come from the controller-served config, so this matters only to someone who can already
write config, but it turns that into reading the pod token.

Recommendation: send the pod token only when `api` is the in-cluster default or an
`https://` URL; refuse (build error) an `http://` `api` that is not loopback; and
require `consul_token_file` to go with an `https://` or loopback `consul_addr`. No
allowlist of paths. Wueschli's call: ship that check in 0.2.0 (small) or defer.

### 4. Gossip quorum denominator (#319 C4-gossip-intent-4)

`quorum_down` divides by the instances that have voted. A backend only some members
check can be declared down by one voter out of one.

Recommendation: **keep the voter denominator** and document it in docs/10. Members of
one domain normally share a config, so all of them vote; a member count would make the
quorum unreachable whenever one member does not check the backend. If a floor is wanted,
add `quorum_min_voters` (default 1) as a setting later rather than change what
`quorum_fraction` means.

### 5. `last_seen` refresh under HA (#319 D2-peers-adopt-1)

Unchanged re-registrations refresh `last_seen` only hourly, so a config-schema floor
computed from `last_seen` ignores live proxies. No effect while `CONFIG_SCHEMA_VERSION`
is 1.

Recommendation: defer with #202 to the first schema bump, then use a node-local
last-heard map (no extra Raft writes) instead of a per-registry touch threshold.

### 6. Stale gossip votes (#278 points 2 and 3)

A forged or stepped `changed_at` is already bounded to 60 s ahead of the receiver's
clock (#318), so the clock-step case costs a minute, not "until time overtakes it". What
remains is a retained vote from a live member whose health task stopped publishing: its
last verdict lives as long as the member does.

Recommendation: the origin re-asserts every verdict every 60 s with a fresh version, and
a receiver ignores a register it has not seen refreshed for 3 minutes. That is one extra
broadcast per backend per minute per instance (bounded by the 8192-backend cap) and
removes both the retained-vote and the stuck-version cases. Not built here because it
changes the wire behaviour and the traffic profile; Wueschli's call: build it for 0.2.0
or leave #278 open as a known limit.
